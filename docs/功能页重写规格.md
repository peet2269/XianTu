# 仙途 · 局内功能页重写规格

> 2026-09-28 整理。用途：左功能栏打开的 14 个功能页要**删掉旧组件、从零重写**。重写时不看旧的 `.vue`，以本文 + 数据层（store / service / utils）为准。
>
> - 版式（线框、L1–L6 版式库）仍按 `docs/UI页面重构设计文档.md` 第 3、5 章，本文与它冲突的地方以本文为准（第 0.3 节列了冲突点）。
> - 本文只写「页面要展示什么、要能做什么、数据从哪来、写到哪去、规则是什么」，以及旧实现里要顺手改掉的结构问题。
> - 提示词后面会统一重构。本文第 17 章把「页面里内联拼提示词」的地方全部列出来，重写页面时先把 AI 调用挪出组件，提示词内容暂时原样搬走。

### 0.2 所有页面共同遵守

1. **页面不画自己的大标题**。标题、副标题、图标、页面级按钮由容器头部统一提供（`GameView.vue` 的 `panelTitles` / `panelActionMap`）。页面内部从正文开始。
2. **只用全局令牌**（`--cc-*` / `--gm-*`，见 `src/styles/xian-tokens.css`、`game-theme.css`）。禁止页面自带一套私有配色——旧设置页自带米黄色浅色主题，就是这么和全局青灰浅色对不上的。
3. **不用 emoji 当图标或按钮**（旧页面大量 `☁️ ⚠️ 📍 🗺️ ⏳ ✅ 🎉 ✏️ 🗑️`），统一 lucide 图标 + 文字。
4. **组件里不写业务逻辑、不拼提示词**。组件只负责展示和收集输入；读写存档、调 AI、计算规则放到 composable / service / utils（每页的「重写后结构」有具体拆法）。
5. **确认一律用统一确认框**。旧代码里有 7 处 `window.confirm`，另有好几页各自手写了确认弹窗，全部换成一个公共的确认组件。
6. **字号用 px 或 rem 都可以**，界面整体大小由设置里的「界面缩放」（`#app` 的 `zoom`）负责；正文类长文本用 `var(--narrative-size)` / `var(--narrative-leading)`。
7. **窄屏**：≤768px 时左右分栏改上下或弹窗，按钮只留图标时要有 `title` / `aria-label`。
8. 容器已设置 `box-sizing: border-box`，页面根元素用 `height: 100%` + 自己负责滚动，不要再给根元素加 `width: 100%` + 左右 padding。

### 0.5 页面级按钮（panelBus）要改

现状：`panelBus` 是全局广播，页面 `onMounted` 注册、从不注销；功能页又被 `keep-alive` 缓存。结果：

- 点「保存游戏」页的「刷新」，缓存着的「记忆」「游戏变量」页也会一起刷新。
- 「世界事件」「大道感悟」页头的「刷新」**没有任何页面监听**，是死按钮。

改法：页面级按钮改成**由页面自己声明**（例如 `usePageActions([{ key, title, icon, onClick, primary? }])`，在 `onActivated` 注册、`onDeactivated` 注销），容器只负责渲染当前激活页面的按钮。`GameView` 里的 `panelActionMap` 随之删除。

## 1. 人物属性

**定位**：只讲「这个人是谁、底子怎样、现在状态如何」。版式 L1：左名牒竖卷 + 右正文。

### 1.1 展示

左名牒（固定）：

- 玉璧头像（名字首字书法）、书法名字、性别 · 种族 · 年龄（年龄由 `character.出生日期` + `gameTime` 算，`utils/lifespanCalculator.calculateAgeFromBirthdate`）。
- 出身（`character.出生`，字符串或 `{名称, 描述}`），可点开看描述。
- 境界：书法境界名（`formatRealmWithStage(attributes.境界)`）+ 进度环（`当前进度 / 下一级所需`）；无「下一级所需」时显示「等待仙缘」不画环；≥90% 显示「可冲刺」，≥100% 显示「可突破」；悬停显示 `境界.突破描述`。
- **四维，和右栏完全同款**：气血 / 灵气 / 神识 / 寿元，图标用 `src/assets/status-icons/blood.png / spirit.png / sense.png / lifespan.png`，数值 `当前 / 上限`，上限 ≤1 或缺失时只显示数值不画条，非寿元低于 30% 数值标红。直接用公共件 `VitalRow`。
- 声望：`reputation.png` 图标 + 称号 + 数值（公共工具）。
- 所在：`location.描述`。

右正文（一页滚动，分节，不再做标签）：

1. **六司**：六边形雷达图 + 六行明细，每行 `最终 = 先天 + 后天`（根骨 / 灵性 / 悟性 / 气运 / 魅力 / 心性）。先天 `character.先天六司`，后天 `character.后天六司`，最终值用 `utils/attributeCalculation.calculateFinalAttributes`（含装备、天赋、功法加成）。缺字段按 0 补齐。
2. **灵根**：名称、品阶、五行元素、修炼速度加成、描述；点开详情弹窗。
3. **天资 · 天赋**：天资档位名；天赋列表（兼容字符串 / `{name, description}` / `{名称, 描述}` 三种存法），点开看描述（找不到描述时查 `data/creationData.LOCAL_TALENTS`）。
4. **状态效果**（可选，右栏已有；打开功能页时右栏隐藏，所以这里放一份只读列表）：`effects`，增 / 减、名称、剩余时间，点开用 `StatusDetailCard` 的内容。
5. **法身**（只在酒馆环境 `utils/tavern` 判定为真时出现）：身高、体重、体脂率、外观特征；三围、罩杯；详细特征；敏感与开发；纹身与印记（字段见 `gameStateStore.body`，敏感内容受 `utils/nsfw` 开关控制）。网页端不显示此节。

## 2. 背包物品

**定位**：物品、法宝装备、钱财。版式 L2：格架 + 详情栏。标签：**物品 / 法宝 / 财产**。

### 2.1 物品

- 数据：`inventory.物品`（`Record<物品ID, Item>`）。Item 关键字段：`名称、类型（装备 / 功法 / 丹药 / 材料 / 其他）、品质 {quality: 凡黄玄地天圣神仙, grade: 0–10 或自定义字符串}、数量、描述、已装备、修炼中、修炼进度、功法效果、功法技能[]、装备增幅、特殊效果、使用效果`。
- 工具条：搜索（名称）、分类（全部 + 实际出现的类型）、排序（默认 / 品质 / 名称）。
- 格子：图标（按类型）+ 品质描边 + 右下数量；已装备「装」、修炼中「修」角标。
- 详情栏：名称（按品质着色）、类型 · 品质 · 品级、描述；功法显示「功法效果」「功法技能（解锁熟练度、消耗）」；装备显示「装备增幅」「特殊效果」。
- 操作：
  | 按钮 | 条件 | 实现 |
  | --- | --- | --- |
  | 装备 / 卸下 | 类型 = 装备 | `enhancedActionQueue.equipItem / unequipItem` |
  | 修炼 / 停止修炼 | 类型 = 功法 | `cultivateItem / stopCultivation`；「是否修炼中」以 `cultivation.修炼功法.物品ID` 为准 |
  | 使用 | 丹药等可用物品 | 选数量 → `enhancedActionQueue.useItem(item, n)` |
  | 丢弃 | 未装备 | 选数量 → 扣数量（为 0 删除）+ `actionQueue.addAction` 记录 + 存档 |
- 同一物品的操作要加忙碌锁，防连点。

### 2.2 法宝

- 数据：`equipment`（`装备1…装备6` → 物品ID）。
- 六个槽位（设计文档：头、身、手、足、佩、器；2×3 或环形），空槽虚线 +「空」；有物品时显示名称、品质、描述、增幅、特效，按钮「卸下」。
- 顶部：已装备数 / 6。

### 2.3 财产

- 数据：新货币系统 `inventory.货币`（`{ 币种: { 名称, 数量, 价值度, 描述, 图标 } }`）+ `inventory.货币设置 { 基准币种, 禁用币种[] }`；旧字段 `inventory.灵石 {下品, 中品, 上品, 极品}` 只做兼容。
- 顶部：总价值（按基准币种折算，书法大数字）+ 当前市场（`worldInfo.经济.地区波动` 按玩家所在地取倍率）。
- 每个币种一行：名称、数量、折算价值；「兑换」「分解」（相邻面额按价值度 × 市场倍率换算）、「删除币种」（写入 `禁用币种`，需确认）。
- **删除确认必须挂在页面根部**（旧版只挂在「物品」标签下，在财产页点删除不弹窗）。

### 2.4 旧实现问题 → 重写时改掉

- 钱包读写、汇率、市场倍率全写在组件里（还有「不要在 computed 里写 inv，否则无限重算」这种注释）→ 抽成 `useWallet()`。
- 丢弃走 `actionQueue` 直接改，装备 / 使用走 `EnhancedActionQueueManager`，两套路子 → 丢弃也放进 `EnhancedActionQueueManager`（顺便支持撤销）。
- 桌面详情栏、手机详情弹窗两份几乎一样的模板 → `ListDetail` 一份模板。
- 「从酒馆同步最新数据」按钮只在酒馆环境显示，保留。

空态：水印「囊」+「空空如也」；筛选为空时「清除筛选」。

## 3. 功法技能

**定位**：主修功法的修炼与突破、已掌握技能、功法库。标签：**修炼 / 掌握技能 / 功法库**。

### 3.1 修炼

- 当前功法 = `inventory.物品` 中 `已装备 === true` 的功法（`cultivation.修炼功法.物品ID` 表示正在修炼）。
- 横幅：书法名、品质、修炼进度（`修炼进度` 0–100）、描述。
- 功法技能：按 `熟练度要求`（旧字段 `解锁需要熟练度`）排成纵向进阶路线；`修炼进度 ≥ 熟练度要求` 即解锁，解锁时写入 `已解锁技能[]` 并存档。
- 操作（都是**通知 AI**，不直接改数值）：
  | 按钮 | 行动队列 type | 说明 |
  | --- | --- | --- |
  | 修炼 | `cultivate` | 「开始修炼《X》」 |
  | 闭关 | `secluded_cultivation` | 「进入闭关状态，专心修炼《X》」 |
  | 深修 | `cultivate` | 弹 `common/DeepCultivationModal` 选天数 →「对《X》进行 N 天的深度修炼」 |
  | 突破 | `breakthrough` | 仅 `修炼进度 ≥ 100` 时出现 |
  | 卸下 | — | 确认 → 若正在修炼先 `stopCultivation` → `characterStore.unequipTechnique(id)` |

### 3.2 掌握技能

- 数据：`masteredSkills[]`（`技能名称、技能描述、来源、消耗、熟练度、使用次数`）。
- 搜索；列表 + 详情。

### 3.3 功法库

## 18. 文风预设（提示词管理 ⇄ 系统设置 联动）

### 18.1 目的

让玩家不碰长提示词也能换文风：选预设即可；想细调就改内容；两处入口改的是同一份数据。

### 18.2 现状问题

文风相关要求散在 5 处，还互相矛盾：

| 位置 | 内容 |
| --- | --- |
| `utils/prompts/definitions/coreRules.ts` `NARRATIVE_PURITY_RULES` | 「字数：800–1500 字」、画面感、结尾留钩子 |
| `utils/prompts/definitions/businessRules.ts` `CULTIVATION_DETAIL_RULES` | 「格调：四字短语 / 古风韵律 / 忌大白话」、度量用词 |
| `services/prompts/defaultPrompts.ts` 分步正文（第 1 步） | 「长度：建议 400–800 字」「叙事风格：多描写少总结」——**和上面的 800–1500 冲突** |
| `utils/prompts/tasks/characterInitializationPrompts.ts` | 「叙事要求与文风：修仙正剧风，语言古朴凝练……」 |
| `utils/prompts/definitions/playerPersonality.ts` | 主角性格（已是独立提示词，可改） |
| 系统设置「自定义行动选项提示词」`uiStore.actionOptionsPrompt` | 行动选项偏好（单独一个文本框） |

### 18.3 设计：风格槽位

把上面这些收拢成几个**槽位**。每个槽位 = 一条提示词（有 key），带若干**预设**，内容可改。

| 槽位 | 管什么 | 预设（第一个为默认） |
| --- | --- | --- |
| 文风 `style.narrative` | 语言格调、描写偏好、节奏、禁用词 | 古典正剧（汇总现有要求）/ 白话通俗 / 轻松诙谐 / 冷峻黑暗 / 细腻抒情 |
| 篇幅 `style.length` | 每回合正文字数，统一主流程和分步第 1 步 | 精简 400–700 / 标准 800–1200 / 详尽 1200–2000 |
| 主角性格 `style.persona` | 现有 `playerPersonality` 迁入 | 正常人（现有默认）/ 杀伐果断 / 温和仁厚 / 谋定后动 / 玩世不恭 |
| 叙事视角 `style.pov` | 人称 | 第三人称（现状）/ 第二人称「你」 |
| 行动选项 `style.options` | 选项的倾向和数量，取代设置里的「自定义行动选项提示词」 | 均衡 / 偏修炼探索 / 偏战斗冒险 / 偏社交谋略 |

每个槽位的状态：`{ presetId, content, customized }`。

- 选预设：`content` = 预设内容，`customized = false`。
- 改内容：`customized = true`，显示「已自定义（基于 古典正剧）」，可「恢复预设」。
- 「另存为我的预设」：用户预设和内置预设放在一起选，可导入导出。

### 18.4 两个入口，一份数据

- 数据：`stylePresetService`（新）——内置预设定义放 `data/stylePresets.ts`；槽位状态和用户预设用 `promptStorage` 存（槽位 key 即提示词 key，`presetId / customized` 作为元数据）；对外提供一个响应式 store `useStylePresets()`。
- **系统设置 →「文风」分组**：每个槽位一行，预设卡片（名称 + 一句说明 + 两三行示例片段）；已自定义时显示标记；「编辑内容」跳到提示词页对应槽位。
- **提示词管理 →「文风与人设」分类**：每个槽位顶部是预设下拉，下面是内容编辑器、「恢复预设」「另存为我的预设」。
- 两边都只调 `useStylePresets()`，所以任一处改动另一处立刻同步。

### 18.5 拼装

- 从 `coreRules`、`businessRules`、分步正文、开局提示词里**删掉**文风、字数、格调相关句子（规则性内容——标记符号、判定格式、禁止暴露数值——留在原处）。
- 主流程、分步第 1 步、开局正文按固定位置注入槽位内容（文风 → 篇幅 → 视角 → 主角性格 → 行动选项）。
- 世界生成、记忆总结、宗门生成等结构化任务**不注入**文风槽位，避免影响 JSON 输出。

### 18.6 已定

- 做「叙事视角」槽位。
- **全局一份 + 存档可覆盖**：全局设置存 `promptStorage`；存档里存 `系统.设置.文风覆盖 = { [槽位]: { presetId, content, customized } }`（只存覆盖了的槽位）。拼装时先取存档覆盖，没有再用全局。
  - 系统设置「文风」分组顶部加切换：「全局默认 / 仅当前存档」；选「仅当前存档」时改动写进存档覆盖，并在每个被覆盖的槽位上显示「本存档」标记和「改回全局」。
  - 提示词管理「文风与人设」分类同样显示「本存档覆盖」状态。
  - 没有载入存档时（局外打开设置 / 提示词页）只能改全局。
